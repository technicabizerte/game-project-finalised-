SNOWPIERCER GAME — IMAGE GENERATION PROMPTS
================================================================================
Game context: 2D side-scrolling platformer set inside the Snowpiercer train.
Player moves left/right, jumps, travels through 5 wagon interiors.
All sprites must have a TRANSPARENT background (PNG).
Style target: pixel art, 16-bit era, crisp edges, no anti-aliasing.
================================================================================


────────────────────────────────────────────────────────────────────────────────
ASSET 1 — PLAYER SPRITE SHEET (player.png)
────────────────────────────────────────────────────────────────────────────────

Required layout:
  - Each frame: 32 pixels wide × 64 pixels tall
  - 3 rows, all frames in a single horizontal strip per row
  - Row 0 (top):    IDLE    — 4 frames, character facing RIGHT
  - Row 1 (middle): WALK    — 6 frames, character facing RIGHT
  - Row 2 (bottom): JUMP    — 2 frames (frame 0 = rising, frame 1 = falling)
  - Total sheet size: 192 × 192 pixels  (6 columns × 3 rows × 32×64)

Character description:
  A thin survivor wearing a worn dark coat, scarf, and boots. Pale cold skin.
  Short dark hair. Snowpiercer / dystopian train passenger aesthetic.
  Hunched slightly forward while walking. Clear silhouette at small size.

PROMPT (Midjourney / DALL-E 3 / Stable Diffusion):

  "2D pixel art sprite sheet of a dystopian train passenger character,
  Snowpiercer aesthetic, worn dark coat and scarf, pale skin, dark hair,
  3 rows of animation: top row 4-frame idle cycle facing right, middle row
  6-frame walk cycle facing right, bottom row 2-frame jump (ascending then
  falling), each frame 32x64 pixels, white or transparent background,
  16-bit game sprite style, clean pixel art, no anti-aliasing, top-down
  side view, consistent character design across all frames"

Alternative shorter prompt:
  "Pixel art game sprite sheet, side-scrolling platformer character,
  dystopian survivor in dark coat and scarf, 3 animation rows: idle (4
  frames), walk (6 frames), jump (2 frames), 32x64 pixels per frame,
  facing right, transparent background, 16-bit style"

Tip: Generate at 2x (64x128 per frame) then scale down to keep pixel clarity.

────────────────────────────────────────────────────────────────────────────────
NOTES FOR GENERATION
────────────────────────────────────────────────────────────────────────────────

1. MOST IMPORTANT: Generate player.png first — it has the biggest visual impact.

2. For pixel art generators (Aseprite AI, PixelLab, etc.) set the palette
   to 32 or 64 colors max for a consistent look across all assets.

3. If using Midjourney: add "--no background, --no shadow" and request
   PNG with alpha. Use "--ar 1:1" for tiles, "--ar 3:1" for floor strips.

4. If the generator cannot produce transparent backgrounds, generate on a
   flat magenta (#FF00FF) background — the code can use SDL colorkey to
   remove it: SDL_SetColorKey(surface, SDL_TRUE, SDL_MapRGB(fmt, 255, 0, 255))

5. Frame order for player.png walk cycle (Row 1, left to right):
   [contact] [down] [passing] [up] [contact] [down]
   Standard 6-frame walk — the character's weight should shift noticeably.

6. Recommend tool: Piskel (free, browser-based) to assemble individual
   frames into the sprite sheet after generation.
